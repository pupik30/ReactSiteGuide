В [уроке 7](../lesson_7/lesson.md) вы сохраняли данные в томах. В этом уроке разберём, что такое микросервисный проект и как запускать несколько контейнеров вместе в Docker.

Цель урока — объединить приложение и сервер Nginx в общей сети и проверить передачу запроса между контейнерами.

Перед началом запустите Docker Desktop (на Linux — Docker Engine) и проверьте:

```bash
docker version
```

В выводе должны быть блоки `Client` и `Server`. Все примеры рассчитаны на Linux-контейнеры.

## Что такое микросервисный проект

В микросервисной архитектуре приложение разделено на самостоятельные сервисы, каждый из которых решает свою задачу и взаимодействует с остальными через определённый интерфейс. Например, каталог товаров и обработка заказов могут быть отдельными сервисами.

Само наличие нескольких контейнеров ещё не делает приложение микросервисным. Сайт, база и Nginx — прежде всего многоконтейнерный стек. На таком небольшом примере удобно изучить техническую основу: отдельные процессы, сетевое взаимодействие и независимый запуск.

## Несколько контейнеров вместо одного

В самостоятельном примере этой лекции используем два компонента:

| Компонент | Назначение | Порт внутри контейнера |
|---|---|---|
| `app` | HTTP-сервер Python, отдаёт страницу | `8000` |
| `gateway` | Nginx, передаёт запросы приложению | `80` |

Браузер обращается к Nginx, а тот — к `app`. На хост публикуем только порт Nginx. Python `http.server` здесь служит маленьким учебным приложением.

В `lessons/lesson_8` создайте каталог `app` и файл `app/index.html`:

```html
<!doctype html>
<html lang="ru">
<meta charset="utf-8">
<title>Несколько контейнеров</title>
<h1>Ответ приложения через Nginx</h1>
</html>
```

Файл `app/Dockerfile`:

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY index.html .
EXPOSE 8000
CMD ["python", "-m", "http.server", "8000", "--bind", "0.0.0.0"]
```

Рядом с каталогом `app` создайте `nginx.conf`:

```nginx
server {
    listen 80;
    location / {
        proxy_pass http://app:8000;
        proxy_set_header Host $host;
    }
}
```

Nginx принимает запрос и отправляет его по адресу `app:8000`. Имя `app` должно разрешаться во внутренней сети Docker.

## Сеть между контейнерами

Создадим пользовательскую bridge-сеть:

```bash
docker network create lesson8-net
```

В такой сети контейнеры могут находить друг друга по имени или сетевому псевдониму. IP-адрес не нужно вручную записывать в конфигурацию. Стандартная сеть `bridge` не даёт такого же автоматического поиска по именам.

Внутренний запрос идёт на порт приложения `8000`. Публикация через `-p` для этого не нужна. `localhost:8000` в настройке Nginx означал бы сам контейнер Nginx, а не Python.

## Запуск без Compose

Все следующие команды выполняйте из `lessons/lesson_8`:

```bash
docker build -t lesson8-app:1 ./app
docker run -d --name lesson8-app --network lesson8-net --network-alias app lesson8-app:1
```

`--network-alias app` даёт контейнеру короткое имя в сети. Проверим ответ из временного контейнера в той же сети:

```bash
docker run --rm --network lesson8-net alpine:3.21 wget -qO- http://app:8000
```

Должен появиться HTML с заголовком страницы. Теперь запустим Nginx. Для Bash/zsh:

```bash
docker run -d --name lesson8-gateway --network lesson8-net -p 127.0.0.1:8088:80 --mount "type=bind,source=$(pwd)/nginx.conf,target=/etc/nginx/conf.d/default.conf,readonly" nginx:stable-alpine
```

Для PowerShell:

```powershell
docker run -d --name lesson8-gateway --network lesson8-net -p 127.0.0.1:8088:80 --mount "type=bind,source=$($PWD.Path)/nginx.conf,target=/etc/nginx/conf.d/default.conf,readonly" nginx:stable-alpine
```

Откройте [сайт](http://localhost:8088). Цепочка запроса:

```text
браузер → localhost:8088 → Nginx:80 → app:8000
```

Если ответа нет, проверьте контейнеры и сеть:

```bash
docker ps -a
docker logs lesson8-gateway
docker logs lesson8-app
docker network inspect lesson8-net
```

Ошибка `host not found in upstream` указывает на проблему имени или сети. Ответ `502 Bad Gateway` часто означает, что Nginx не может подключиться к приложению. В этом простом примере запускайте приложение до Nginx. После пересоздания приложения с новым IP перезапустите Nginx, чтобы он заново разрешил имя.

## Практика

1. Создайте файлы, сеть и оба контейнера.
2. Прочитайте страницу через временный контейнер и через браузер.
3. Выполните `docker stop lesson8-app`, обновите страницу и посмотрите журнал Nginx.
4. Верните приложение командой `docker start lesson8-app`. Проверьте, что страница снова доступна.
5. Завершите эксперимент:

```bash
docker stop lesson8-gateway lesson8-app
docker rm lesson8-gateway lesson8-app
docker network rm lesson8-net
```

Сохраните исходные файлы: в следующей лекции перенесём эту конфигурацию в Compose.

## Кратко

- Каждый компонент можно запускать в отдельном контейнере.
- Пользовательская сеть позволяет обращаться по именам.
- Наружу публикуем точку входа, а между контейнерами используем внутренние порты.
- При росте числа компонентов ручные команды удобнее заменить декларативным описанием.
