# Урок 7. Работа с томами (volumes)

Ролик: [#7. Работа с томами (volumes)](https://rutube.ru/video/90117c0ee13fa2cef65980eec6172d36/)
Плейлист: [Docker для начинающих](https://rutube.ru/plst/859340/)

> Материал развивает тему указанного ролика и исходный план лекции. Полная расшифровка видео при подготовке недоступна; примеры ниже — самостоятельная практика, а не дословное воспроизведение действий автора. Справочные ссылки приведены в конце.

В [уроке 6](../lesson_6/lesson.md) вы пробросили порты из хоста в контейнер. В этом уроке разберём, как сохранять данные вне контейнера: три способа монтирования томов.

Цель урока — сохранить данные после удаления контейнера и сравнить bind mount, именованный и анонимный том.

Перед началом запустите Docker Desktop (на Linux — Docker Engine) и проверьте:

```bash
docker version
```

В выводе должны быть блоки `Client` и `Server`. Все примеры рассчитаны на Linux-контейнеры.

## Зачем нужны тома

Остановка контейнера не удаляет его файлы. Но при **удалении** контейнера его записываемый слой исчезает. Для данных, которые должны пережить пересоздание, подключают внешнее хранилище.

Разберём три варианта подключения: каталог хоста (bind mount), именованный том и анонимный том. Строго говоря, bind mount — отдельный тип монтирования, а последние два варианта — Docker volumes.

## Bind mount: каталог хоста

Этот вариант удобен, когда файлы нужно редактировать на компьютере и сразу видеть в контейнере. В папке `lessons/lesson_7` создайте каталог `site`, а в нём `index.html`:

```html
<!doctype html>
<html lang="ru">
<meta charset="utf-8">
<title>Тома Docker</title>
<h1>Страница из каталога компьютера</h1>
</html>
```

Откройте терминал в `lessons/lesson_7`. Для Bash/zsh:

```bash
docker run -d --name lesson7-web -p 127.0.0.1:8087:80 --mount "type=bind,source=$(pwd)/site,target=/usr/share/nginx/html,readonly" nginx:stable-alpine
```

Для PowerShell:

```powershell
docker run -d --name lesson7-web -p 127.0.0.1:8087:80 --mount "type=bind,source=$($PWD.Path)/site,target=/usr/share/nginx/html,readonly" nginx:stable-alpine
```

Каталог `site` должен существовать до запуска. Если занят порт `8087`, завершите пример предыдущего урока или выберите другой порт хоста.

Откройте [страницу](http://localhost:8087), измените заголовок в файле на компьютере и обновите браузер. Пересборка не требуется: Nginx читает подключённый каталог. `readonly` запрещает контейнеру изменять файлы этого подключения. Монтирование скрывает прежнее содержимое `/usr/share/nginx/html` из образа.

## Именованный том

Томом управляет Docker. Вы задаёте имя, а не путь к каталогу компьютера. Запишем и прочитаем строку из двух разных одноразовых контейнеров:

```bash
docker volume create lesson7-data
docker run --rm --mount type=volume,source=lesson7-data,target=/data alpine:3.21 sh -c "echo Hello-volume > /data/message.txt"
docker run --rm --mount type=volume,source=lesson7-data,target=/data,readonly alpine:3.21 cat /data/message.txt
```

Первый контейнер удалён благодаря `--rm`, но второй выводит `Hello-volume`: именованный том продолжает существовать. Такой принцип нужен для файлов баз данных и других долговечных данных.

Том не является резервной копией: случайное удаление или изменение файла приложением меняет данные самого тома.

## Анонимный том

Если указать только путь внутри контейнера, Docker создаст том со случайным именем:

```bash
docker run --name lesson7-anon -v /data alpine:3.21 sh -c "echo Anonymous > /data/message.txt"
docker inspect lesson7-anon
```

Найдите раздел `Mounts`: в нём будут тип `volume`, имя и путь назначения. Новый запуск с `-v /data` создаёт другой том, а не подключает предыдущий автоматически.

В этом примере контейнер остановился, но не удалился. Команда ниже удалит его вместе с подключённым анонимным томом:

```bash
docker rm -v lesson7-anon
```

При обычном `docker rm` анонимный том остаётся. Флаг `--rm` при запуске автоматически удаляет связанный анонимный том вместе с контейнером; именованные тома сохраняются.

## VOLUME в Dockerfile

```dockerfile
VOLUME ["/data"]
```

Инструкция объявляет точку монтирования. Если при запуске не задать своё подключение к `/data`, Docker создаст анонимный том. Для постоянных данных удобнее явно задать именованный том через `--mount` или Compose.

`VOLUME` не указывает каталог на вашем компьютере. Местоположение данных на хосте выбирается механизмом хранения Docker.

## Команды `docker volume`

```bash
docker volume ls
docker volume inspect lesson7-data
```

После завершения практики и проверки, что данные больше не нужны, можно удалить **только учебный том**:

```bash
docker volume rm lesson7-data
```

Подключённый к существующему контейнеру том Docker удалить не даст. Общую команду `docker volume prune` в этом курсе не выполняем: неиспользуемый том другого проекта всё ещё может содержать нужные данные.

## Практика

1. Измените HTML на компьютере и проверьте обновление без пересборки.
2. Запишите строку в `lesson7-data`, затем прочитайте её новым контейнером.
3. Найдите анонимный том в `inspect` и удалите его через `docker rm -v lesson7-anon`.
4. Завершите пример Nginx:

```bash
docker stop lesson7-web
docker rm lesson7-web
```

5. Убедитесь, что `site/index.html` остался на компьютере. Удаление контейнера не удаляет файлы bind mount.
6. Удалите `lesson7-data`, только если эксперимент с ним окончен.

## Кратко

- Bind mount удобен для файлов, редактируемых на компьютере.
- Именованный том удобно повторно подключать по имени.
- Анонимный том получает случайное имя и не переиспользуется автоматически.
- Удаление контейнера и удаление данных тома — разные действия.
