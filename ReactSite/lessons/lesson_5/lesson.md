# Урок 5. Углубляемся в команды docker

Ролик: [#5. Углубляемся в команды docker](https://rutube.ru/video/9e6a22bd4656f454a5b787f3e492d61f/)
Плейлист: [Docker для начинающих](https://rutube.ru/plst/859340/)

> Материал развивает тему указанного ролика и исходный план лекции. Полная расшифровка видео при подготовке недоступна; примеры ниже — самостоятельная практика, а не дословное воспроизведение действий автора. Справочные ссылки приведены в конце.

В [уроке 4](../lesson_4/lesson.md) вы разобрали особенности сборки образов и очистку кэша. В этом уроке углубимся в команды для работы с контейнерами и образами, в том числе в составные команды.

Цель урока — управлять жизненным циклом контейнера, читать журналы и находить нужные ресурсы по фильтрам.

Перед началом запустите Docker Desktop (на Linux — Docker Engine) и проверьте:

```bash
docker version
```

В выводе должны быть блоки `Client` и `Server`. Все примеры рассчитаны на Linux-контейнеры.

## Манипуляции с контейнерами

`docker run` каждый раз создаёт **новый** контейнер. `docker start` запускает уже существующий, сохраняя его имя и настройки. Для примера запустим Nginx в фоне:

```bash
docker run -d --name lesson5-web --label course.lesson=5 nginx:stable-alpine
docker ps
docker ps -a
```

`-d` освобождает терминал; `--name` задаёт удобное имя, а `--label` — метку для поиска. Порт пока не публикуем: доступ из браузера разберём в следующем уроке.

Попробуйте остановку и повторный запуск:

```bash
docker stop lesson5-web
docker ps -a
docker start lesson5-web
docker restart lesson5-web
```

После `stop` контейнер остаётся в списке со статусом `Exited`. После `start` снова получает статус `Up`. Если повторить исходный `run` с тем же именем, Docker сообщит о конфликте: имя занято существующим контейнером.

Для диагностики:

```bash
docker logs --tail 20 lesson5-web
docker inspect lesson5-web
docker stats --no-stream lesson5-web
docker top lesson5-web
```

`logs` показывает стандартный вывод и ошибки основного процесса, `inspect` — подробные настройки, `stats` — потребление ресурсов, `top` — процессы. Для наблюдения за новыми строками используйте `docker logs -f lesson5-web`; `Ctrl+C` завершает просмотр журнала.

Выполним дополнительную команду внутри работающего контейнера:

```bash
docker exec lesson5-web nginx -v
docker exec -it lesson5-web sh
```

В открывшейся оболочке выполните `pwd`, затем `exit`. Завершится дополнительная оболочка, Nginx продолжит работу. В Alpine обычно нет `bash`, поэтому используем `sh`. `exec` нельзя выполнить в остановленном контейнере.

`docker attach` подключается к основному процессу, поэтому его не следует путать с `exec`: сигналы из терминала могут воздействовать на само приложение.

## Манипуляции с образами

```bash
docker image ls
docker image inspect nginx:stable-alpine
docker image history nginx:stable-alpine
docker image tag nginx:stable-alpine lesson5-nginx:demo
docker image ls lesson5-nginx
```

`tag` создаёт дополнительное имя образа, а не полную копию его слоёв. Сравните IMAGE ID у двух тегов.

Образ можно перенести архивом. Следующие команды выполняйте в папке `lessons/lesson_5`:

```bash
docker image save -o lesson5-nginx.tar lesson5-nginx:demo
docker image rm lesson5-nginx:demo
docker image load -i lesson5-nginx.tar
```

`save/load` работают с образами и их метаданными. `export/import` работают с файловой системой контейнера и не являются равноценной заменой сохранению образа.

## Составные команды

Флаг `-q` выводит только идентификаторы. Фильтр позволяет ограничить выборку учебными контейнерами:

```bash
docker ps -a --filter label=course.lesson=5
docker ps -aq --filter label=course.lesson=5
```

Сначала просмотрите полную таблицу и убедитесь, что в ней только контейнеры этого урока. Затем их можно остановить и удалить через подстановку результата команды.

Для Bash/zsh (macOS, Linux, WSL):

```bash
for id in $(docker ps -aq --filter label=course.lesson=5); do
  docker stop "$id"
  docker rm "$id"
done
```

Для PowerShell:

```powershell
docker ps -aq --filter label=course.lesson=5 | ForEach-Object {
    docker stop $_
    docker rm $_
}
```

Если подходящих контейнеров нет, тело цикла не выполнится. Не убирайте фильтр: удаление всех контейнеров затронет и другие проекты.

Для одного объекта проще указать имя явно: `docker stop lesson5-web`, затем `docker rm lesson5-web`. После удаления контейнер уже нельзя запустить через `start`: нужен новый `run`.

## Практика

1. Создайте Nginx с именем и меткой из примера.
2. Остановите и снова запустите его; проверьте статусы в `ps -a`.
3. Выведите версию Nginx через `exec`, прочитайте журналы и расход ресурсов.
4. Создайте дополнительный тег образа, сохраните его и загрузите из архива.
5. Найдите контейнер по метке, затем удалите его приведённым циклом.
6. Удалите учебный тег командой `docker image rm lesson5-nginx:demo`. Архив при необходимости удалите через файловый менеджер.

## Кратко

- `run` создаёт контейнер, `start` запускает существующий.
- `exec` запускает дополнительный процесс внутри работающего контейнера.
- Метки и фильтры помогают адресно выбирать ресурсы.
- Перед удалением проверяйте список выбранных объектов.
