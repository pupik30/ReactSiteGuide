В [уроке 8](../lesson_8/lesson.md) вы запускали микросервисы отдельными командами. В этом уроке опишем и поднимем то же самое одной командой через Docker Compose.

Цель урока — описать знакомый стек в YAML, запустить его одной командой и освоить основные команды Compose.

Перед началом запустите Docker Desktop (на Linux — Docker Engine) и проверьте:

```bash
docker version
```

В выводе должны быть блоки `Client` и `Server`. Все примеры рассчитаны на Linux-контейнеры.

## Что такое Docker Compose

В прошлом уроке мы отдельно собирали образ, создавали сеть и запускали два контейнера. Docker Compose хранит эти настройки в файле: какие сервисы нужны, откуда брать образы, какие порты и каталоги подключить.

Проверьте доступность команды:

```bash
docker compose version
```

В материалах используется современная запись `docker compose` с пробелом. Если команда недоступна на Linux, установите [Compose plugin](https://docs.docker.com/compose/install/linux/). В старых видео можно встретить отдельную программу `docker-compose`.

## Файл `docker-compose.yml`

Откройте `lessons/lesson_9`. Скопируйте сюда каталог `app` и файл `nginx.conf`, созданные в уроке 8. Редактировать исходную папку урока 8 не нужно. Структура:

```text
lesson_9/
├── lesson.md
├── docker-compose.yml
├── nginx.conf
└── app/
    ├── Dockerfile
    └── index.html
```

Создайте `docker-compose.yml`:

```yaml
name: docker-lesson9

services:
  app:
    build: ./app
    networks:
      - lesson_net

  gateway:
    image: nginx:stable-alpine
    ports:
      - "127.0.0.1:8089:80"
    volumes:
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on:
      - app
    networks:
      - lesson_net

networks:
  lesson_net:
```

YAML использует отступы пробелами. Табуляцию не применяйте. Верхнеуровневый `version` для этого файла не нужен.

`build: ./app` задаёт контекст сборки. `image` у Nginx указывает готовый образ. `ports` соответствует `-p`, а `volumes` здесь подключает файл конфигурации только для чтения. Относительные пути относятся к каталогу Compose-файла при таком одиночном файле проекта.

## Сервисы, сети и тома

**Сервис** — описание компонента, из которого Compose создаёт контейнер. В командах Compose используем имя сервиса `app` или `gateway`; конкретные имена контейнеров Compose назначает сам.

`name: docker-lesson9` задаёт имя проекта, чтобы его ресурсы было легче отличать от других. Оба сервиса подключены к `lesson_net`, поэтому Nginx находит приложение по имени `app`. Если блок `networks` не указывать, Compose создаёт общую сеть `default`.

В этом примере постоянные данные не нужны. Для именованного тома его объявляют на верхнем уровне и подключают к нужному сервису. Например, такой фрагмент описывает хранение в `/data` (это пояснение синтаксиса, заменять им полный файл не нужно):

```yaml
services:
  app:
    build: ./app
    volumes:
      - app_data:/data
volumes:
  app_data:
```

`depends_on` в краткой форме задаёт порядок запуска, но не ждёт готовности HTTP-сервера. Сразу после старта возможен кратковременный `502`; повторите запрос. В следующем уроке используем проверки готовности.

## Команды `up` и `down`

Откройте терминал в `lessons/lesson_9`:

```bash
docker compose config
docker compose up -d --build
docker compose ps
docker compose logs --tail 20
```

`config` проверяет и показывает итоговое описание. `up` создаёт сеть и контейнеры, а при необходимости обновляет их. `--build` запускает сборку, `-d` оставляет сервисы в фоне.

Откройте [страницу проекта](http://localhost:8089). Внутри используется та же цепочка Nginx → Python, что и в уроке 8.

Полезные команды:

```bash
docker compose logs -f gateway
docker compose exec app python --version
docker compose stop
docker compose start
```

Из просмотра журнала выйдите через `Ctrl+C`, затем выполняйте остальные команды. `stop/start` останавливают и запускают существующие контейнеры. Для применения изменений образа используйте `up -d --build`: `restart` сам по себе код в образе не пересобирает.

Завершение проекта:

```bash
docker compose down
```

Команда удаляет контейнеры и сети проекта. Именованные тома по умолчанию остаются; опция `-v` также удаляет тома проекта и их данные, поэтому не добавляйте её к обычному завершению работы.

## Практика

1. Скопируйте файлы примера из урока 8 и создайте Compose-файл.
2. Выполните `config`, затем `up -d --build`.
3. Проверьте страницу и журнал `gateway`.
4. Измените текст в `app/index.html`. Пересоберите через `up -d --build` и проверьте результат. При временном `502` после пересоздания приложения выполните `docker compose restart gateway`.
5. Выполните `down`, затем снова `up -d --build`. Проверьте, что стек создаётся по файлу без ручных `docker run`.
6. Завершите практику командой `down`.

## Кратко

- Compose описывает компоненты приложения в одном YAML-файле.
- Сервисы общей сети обращаются друг к другу по именам.
- `up` создаёт или обновляет стек, `down` удаляет его контейнеры и сети.
- Порядок запуска и готовность приложения — разные вещи.
