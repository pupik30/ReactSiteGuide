В [уроке 5](../lesson_5/lesson.md) вы продолжили работу с командами Docker. В этом уроке разберём, как запрос из внешней сети хоста попадает во внутреннюю сеть Docker и в контейнер.

Цель урока — открыть сайт из контейнера в браузере и понять разницу между портом хоста и портом приложения.

Перед началом запустите Docker Desktop (на Linux — Docker Engine) и проверьте:

```bash
docker version
```

В выводе должны быть блоки `Client` и `Server`. Все примеры рассчитаны на Linux-контейнеры.

## Зачем нужны порты

IP-адрес помогает найти компьютер или сетевой интерфейс, а порт — нужное приложение. Например, Nginx в нашем образе принимает HTTP-запросы на TCP-порту `80`.

У хоста и контейнера разные сетевые пространства. Приложение внутри контейнера может слушать порт `80`, пока на компьютере этот порт занят другой программой. Конфликт возникает, если два приложения пытаются занять один и тот же адрес и порт **на хосте**.

## Внутренняя сеть Docker

При обычном запуске Docker подключает контейнер к bridge-сети. Контейнер получает внутренний адрес. В Docker Desktop эта сеть находится внутри Linux-виртуальной машины; обращаться к IP контейнера из браузера хоста обычно не нужно.

Посмотреть настройки можно так:

```bash
docker network ls
docker network inspect bridge
```

Внутри контейнера `localhost` обозначает сам контейнер. Это не адрес вашего компьютера и не адрес соседнего контейнера. Общение контейнеров по именам разберём в уроке 8.

## Проброс портов: `-p хост:контейнер`

Запустим Nginx:

```bash
docker run -d --name lesson6-web -p 127.0.0.1:8086:80 nginx:stable-alpine
```

Сопоставление читается слева направо:

```text
браузер → 127.0.0.1:8086 на хосте → порт 80 контейнера → Nginx
```

- `127.0.0.1` ограничивает публикацию локальным компьютером.
- `8086` — порт, который вводим в адресной строке браузера.
- `80` — порт, на котором слушает Nginx внутри контейнера.

Короткая запись `-p 8086:80` обычно публикует порт на всех интерфейсах хоста. Для локальной практики используем явный адрес `127.0.0.1`.

Можно запустить второй контейнер с тем же внутренним портом, но другим внешним:

```bash
docker run -d --name lesson6-second -p 127.0.0.1:8087:80 nginx:stable-alpine
```

Оба Nginx слушают `80`, но браузер различает их по `8086` и `8087`. Изменить публикацию портов существующего контейнера командой `start` нельзя — контейнер потребуется пересоздать.

## EXPOSE в Dockerfile

```dockerfile
EXPOSE 80
```

Эта строка описывает предполагаемый порт приложения. Она не запускает сервер и сама по себе не публикует порт на хосте. Даже без `EXPOSE` явный `-p` работает, если процесс действительно слушает нужный порт.

`docker run -P` публикует объявленные порты на автоматически выбранных портах хоста; узнать их можно через `docker port`. Для повторяемой практики удобнее явное сопоставление.

Если запускаете свой веб-сервер на Python или другом языке, привяжите его внутри контейнера к `0.0.0.0`, а не только к `127.0.0.1`. Например, `python -m http.server 8000 --bind 0.0.0.0`; тогда сопоставление должно оканчиваться на `:8000`.

## Проверка из браузера и с хоста

Откройте [первый сервер](http://localhost:8086) и [второй сервер](http://localhost:8087). Должна появиться стандартная страница Nginx.

```bash
docker port lesson6-web
docker logs --tail 20 lesson6-web
```

В Bash/zsh запрос можно проверить командой `curl -I http://localhost:8086`. В PowerShell используйте `Invoke-WebRequest http://localhost:8086`.

Если страница не открывается:

1. Проверьте `docker ps -a`: контейнер должен быть запущен.
2. Сверьте внешний порт через `docker port lesson6-web`.
3. Прочитайте `docker logs lesson6-web`.
4. При ошибке `port is already allocated` выберите другой свободный порт хоста. Если неудачный запуск оставил контейнер в статусе `Created`, удалите только его перед повторным `run`.

## Практика

1. Поднимите оба контейнера и откройте обе страницы.
2. Объясните, почему одинаковый порт `80` не создаёт конфликт.
3. Посмотрите публикацию портов через `docker port`.
4. Остановите первый контейнер и проверьте, что второй сайт продолжает работать.
5. Удалите учебные контейнеры:

```bash
docker stop lesson6-web lesson6-second
docker rm lesson6-web lesson6-second
```

## Кратко

- В адресе браузера указывают порт хоста, а не внутренний порт контейнера.
- `-p` задаёт публикацию; `EXPOSE` только описывает порт.
- `localhost` внутри контейнера относится к самому контейнеру.
